# 圆形记账入口与交互卡顿治理设计

日期：2026-07-17

## 背景与问题

当前根页面使用 `TabView.tabViewBottomAccessory` 承载“+ 记一笔”。在 iPhone 17 Pro、iOS 26.5 的只读 UI 自查中，按钮本身约为 152×48pt，但系统还会为它创建约 360×48pt 的独立附件行。该行与 Tab Bar、安全区合计占据约 139pt 的底部区域，明显压缩内容空间。

附件还依赖 `tabViewBottomAccessoryPlacement`，会在滚动触发 Tab Bar 收缩时，从“+ 记一笔”宽按钮变成只有加号的紧凑按钮。这会同步改变尺寸、文字和玻璃材质，是当前小数据集下仍会发生的布局重排与视觉抖动来源。

用户已确认参考 iCost 的“独立圆形按钮”思路，但保留本应用自身的蓝色品牌色和现有记账流程，不复制 iCost 的配色、页面比例或视觉资产。

## 目标

1. “记一笔”改为不占独立行的圆形悬浮主按钮。
2. 保留四个等宽 Tab 的原生导航语义和命中区域。
3. 减少当前与数据量无关的布局重排、慢按压反馈和重复合成层。
4. 不改变账单数据模型、保存流程、入口权限或现有记账 Sheet 的业务行为。
5. 通过 Release 构建和模拟器 UI 回归验证真实布局与交互。

## 已选方案

### 根级圆形悬浮入口

- 删除根 `TabView` 的 `.tabViewBottomAccessory` 和对 `tabViewBottomAccessoryPlacement` 的依赖。
- 在根视图上使用不参与内容布局的 overlay 放置圆形按钮。
- 按钮位于右下角，视觉直径固定为 56pt、右侧间距 20pt、位于可见 Tab Bar 上方 18pt；底部安全区变化只影响定位，不改变按钮尺寸。
- 按钮使用白色粗体 `plus`，保留本应用蓝色强调色；命中形状和视觉形状均为 `Circle`。
- 短按继续调用现有 `RootPresentationState.presentNewEntry`，打开原有 `EntryView`。
- 本轮不新增 iCost 的“长按模板”行为，避免把 UI 修复扩展成新的功能入口；现有模板能力仍保留在记账页内。
- 按钮的无障碍标签继续为“记一笔”，提示为“新建一笔交易”，命中区域不小于 44×44pt。
- 进入隐藏 Tab Bar 的详情页时，悬浮按钮必须同步隐藏，避免覆盖详情内容。使用按 Tab 标识的可见性 Preference 向根视图上报，根视图只读取当前选中 Tab 的值，防止后台 Tab 的导航栈影响当前入口。

不采用以下方案：

- 中间凸起按钮：会压到当前“资产/计划”两个 Tab 的命中区域，并模糊普通 Tab 与主操作之间的语义。
- 在 `tabViewBottomAccessory` 内只把按钮改圆：外层整行仍然保留，无法解决空间占用和滚动重排。

## 卡顿治理范围

本轮只处理与当前投诉直接相关、风险可控的热点：

1. 移除 accessory placement 驱动的宽度、文字和玻璃材质重排。
2. 为高频按钮按压新增独立的快速曲线：按下约 120ms、释放约 100ms；不全局缩短 `LedgerMotion.responsive`，避免影响仪表盘、分类展开和储蓄状态动画。
3. 资产根页不再订阅整份 `Environment`，改为窄化读取无障碍转场偏好，避免底部环境变化连带重算资产摘要和列表。
4. 记账页横向分类从 `HStack` 改为 `LazyHStack`；重复分类卡只保留填充和描边，取消不必要的逐卡阴影，降低首次弹出 Sheet 的合成成本。
5. 月份切换不再把整棵摘要和流水替换放进统一 `withAnimation` 事务；保留必要的局部数字/进度动画。
6. 对金额格式化器进行安全复用或改用 `FormatStyle`，减少滑动手势期间的临时对象分配。
7. 资产卡 zoom 转场先做 `.automatic`/cross-fade A/B 验证；只有确认 zoom 是剩余 hitch 的来源时才调整默认转场，避免无证据改变已批准的资产动效。

不会在本轮进行 SwiftData 查询架构重写。当前测试数据规模很小，全历史查询是未来扩展风险，但不能解释当前已经出现的大量卡顿。

## 组件与数据流

`RootTabView` 继续拥有唯一的 `RootPresentationState`。圆形按钮只发送一个 `presentNewEntry` 事件，不读取或修改账本、账户、分类数据。`RootEntryPresenter` 仍负责展示记账 Sheet，因此入口改造不会产生第二套展示状态，也不会改变保存和错误处理路径。

高频按压曲线放在共享 UI 组件中，但与页面状态动画分离。记账分类懒加载和表面阴影调整只改变渲染方式，不改变分类选择绑定、展开逻辑或交易表单状态。

## 边界与错误处理

- 没有可用账户时，短按圆钮仍进入现有空状态，由 `EntryView` 提示先创建账户。
- 连续快速点击由现有单一 `RootPresentationState` 控制，不创建重叠 Sheet。
- 键盘显示时不改变根入口业务状态；记账 Sheet 覆盖期间根按钮不可交互。
- 开启“减少动态效果”时，按钮只使用短淡化/无缩放反馈；开启“降低透明度”时保持足够对比度。
- 横竖屏和不同底部安全区由容器安全区定位处理，不写死屏幕高度。

## 验收标准

### 布局

- 四个 Tab 保持等宽且均可正常点击。
- 根页面底部不再出现独立的“记一笔”附件行。
- 圆形按钮视觉直径 56pt，命中区域至少 44pt，右下悬浮且不遮挡最后一条主要内容。
- 流水、资产、计划、报表四个根 Tab 均显示入口；隐藏 Tab Bar 的详情页不显示入口。

### 交互与性能

- 短按圆钮立即出现按压反馈并打开现有记账页。
- 连续滚动和 Tab Bar 最小化时，按钮不改变宽度、不增删文字、不触发附件行重排。
- 连续切换四个 Tab、连续打开/关闭记账页、横滑资产卡和进入/退出资产详情无明显 hitch。
- 记账页首次打开时分类横向列表可立即滚动，分类选择与展开行为不变。
- 月份切换不再带动整页列表做隐式动画。

### 验证

- 运行现有单元测试。
- 使用 Release 配置构建 iOS Simulator 目标。
- 在 iPhone 17 Pro / iOS 26.5 或当前可用的 iOS 26+ 模拟器完成 UI 截图和命中区域检查。
- 对 Debug 与 Release 的滚动和转场做相对 A/B；最终性能结论以 Release 为准。
- 检查 Reduce Motion、深色模式和至少一种较大动态字体设置。

## 非目标

- 不复制 iCost 的黄色按钮、Tab 图标、页面比例或模板页。
- 不新增长按模板、语音记账或其他快捷入口。
- 不重做记账表单、资产卡视觉设计或 Tab 信息架构。
- 不在本轮迁移全部 SwiftData 查询或引入新的状态管理框架。
