# iCost 功能等价补全设计

日期：2026-07-13  
状态：待用户书面审阅  
目标：在现有 MultiCurrencyLedger 的数据、视觉和交互基础上，补齐本机 iCost 4.6.2 / 官方 4.6.3 功能中尚未覆盖的能力；已有功能若账务语义更严谨则覆盖底层逻辑，但不复制 iCost 的 UI。

## 1. 范围与原则

### 1.1 产品原则

- 保留当前 SwiftUI + SwiftData 架构、现有玻璃视觉体系和多账本/多币种基础。
- 功能对齐，不做 UI 复刻；iCost 只作为功能与账务语义参照。
- 所有新入口共享同一套草稿、校验、余额影响和统计规则。
- 迁移优先于重置；已有账本、账户、钱包、交易、预算和截图识别记录不得因补功能而丢失。
- 小组件和位置附件延后；本阶段仍支持图片附件。
- 非必要不运行 Simulator。纯逻辑优先用单元测试和内存 SwiftData；仅在阶段性 UI、URL Scheme/App Intent、系统权限和最终回归时使用。

### 1.2 目标功能矩阵

本项目现有基础：多账本、多币种钱包、支出/收入/转账/换汇/调整、基础余额更新、月度总预算、资产估值、CSV/JSON 导出、截图识别与快捷指令入口、基础搜索筛选、分类和汇率管理。

补全目标：

- 核心流水：完整交易编辑、复制、关键词/日期/金额/账本/账户/币种/类型/分类/标签筛选、排序、账本与月份隔离。
- 分类与交易属性：二级分类、标签、多付款账户、商户、图片附件、模板、批量操作。
- 交易关系：多次部分退款、待报销/报销入账、个人实际承担金额。
- 自动化：周期入账、消费分期、信用账单分期、独立 URL Scheme、文本/语音/截图统一确认入口。
- 资产与计划：资产/负债/净资产解释、资产对账、周/月/年总预算和分类预算、存钱目标与分配历史。
- 数据：通用 CSV/XLSX 列映射及常用平台预设、批量导入预览/去重/撤销、完整 JSON 备份与恢复。
- 平台与安全：50+ 常用币种、iCloud 私有同步、密码/Face ID/Touch ID、后台遮挡、秒开模式、深色模式兼容。

延后清单：桌面/锁屏小组件、位置附件。

## 2. 账务内核

### 2.1 统一提交路径

新增 `TransactionDraft`、`TransactionValidation`、`WalletDelta` 和统一提交服务。手工新增、编辑、复制、模板、退款、报销、周期、分期、截图识别、文本/语音识别和 URL Scheme 都只负责生成草稿，不直接改 SwiftData 钱包余额。

统一提交流程：

1. 解析并清洗草稿字段。
2. 校验金额、币种、账户/钱包归属、分类类型、手续费、日期、关系交易和账本范围。
3. 将草稿计算为明确的 `WalletDelta` 列表。
4. 在同一 ModelContext 批次内反算旧流水（编辑/删除时）并应用新影响。
5. 保存交易、关系、附件元数据和钱包余额；任一步失败恢复原交易和原余额。
6. 由同一批流水刷新资产、预算、统计和明细查询。

现有单钱包交易继续可读。组合付款增加付款明细关系；旧交易通过适配器映射为单一付款明细，不强制重写历史数据。

### 2.2 余额和统计语义

- 支出减少付款钱包；收入增加收款钱包。
- 转账和换汇本金只改变钱包位置，不计入收入/支出或净资产变化。
- 手续费作为支出计入预算和现金流。
- 退款关联原支出，按原支出金额和分类冲减；多次部分退款累计不得超过可退金额。
- 报销入账关联待报销支出，单独展示已报销和个人实际承担，不把报销误报为普通收入。
- 存钱目标是独立分配记录，不虚构钱包转账，不重复减少资产。
- 所有折算使用一个集中汇率策略；缺失汇率必须显式提示，不能静默按 1:1。

### 2.3 数据模型增量

保留现有模型并增量加入以下实体/属性：

- 分类父子关系与账本作用域。
- `TransactionTag` / 标签关联。
- `TransactionPaymentPart` / 多账户付款明细。
- `TransactionRelation` / 退款、报销、分期来源等关系。
- `TransactionAttachment` / 图片路径、缩略图、创建时间和校验值。
- `TransactionTemplate` / 模板草稿快照和最近使用时间。
- `RecurringSchedule` / 周期规则、下一次日期、唯一生成键、暂停/归档状态。
- `InstallmentPlan` / 消费分期或账单分期、期数、每期金额、手续费、生成状态。
- `SavingsGoal` 与 `SavingsAllocation` / 目标和独立的增加/减少分配流水。
- 导入批次、备份元数据、同步冲突副本和 URL Scheme 待确认草稿记录。

所有新关系都有明确的删除/归档规则；有历史交易的账户、分类、账本和目标不得级联删除历史流水。

## 3. 功能与交互

### 3.1 核心流水和搜索

当前账本和月份是首页、预算、资产解释和每日明细的共同范围。交易明细默认当前账本，可切换全部账本。查询状态由纯值模型统一保存，支持：

- 关键词匹配商户、备注、分类、来源/目标账户；忽略大小写和首尾空白。
- 全部、本月、近 30 天、今年、自定义起止日期。
- 最小/最大金额，转账/换汇按来源金额匹配。
- 账户、币种、类型、分类、标签、账本。
- 日期倒序/正序、金额高到低/低到高。

交易详情支持完整编辑、复制为新交易和删除。复制默认使用当前日期，金额必须由用户确认。

### 3.2 分类、标签、附件、模板和批量

- 录入页保留快速路径，复杂字段放入“更多选项”。
- 二级分类可在分类管理中新增、改名、排序、归档；父分类和子分类均可用于统计。
- 标签支持一笔交易多选、搜索和批量赋值。
- 图片进入 App 沙盒，数据库只保存引用、缩略图信息和校验值；附件损坏时交易仍可读取。
- 模板只保存可验证的草稿配置。使用模板时重新检查账户、币种、分类、账本和手续费规则。
- 批量修改先预览影响，整批验证通过后提交；失败不得留下部分修改。

### 3.3 退款与报销

原支出详情提供“发起退款”和“标记待报销”。退款可多次部分入账并选择收款钱包；报销入账必须关联原支出，可记录报销日期、来源和金额。详情与统计同时展示原金额、已退/已报销、剩余可退和个人承担。

### 3.4 周期和分期

周期规则生成普通交易草稿，支持暂停、恢复、补生成和归档；唯一生成键保证重复打开 App 或同步不会重复入账。

消费分期关联原消费并生成期次；账单分期关联信用账户账单并记录本金、手续费、期数和还款状态。两种分期共用生成和撤销框架，但在预算和资产解释中保持不同语义。

### 3.5 URL Scheme 与智能入口

注册独立于 iCost 的自有 Scheme，例如 `multiledger://entry`。参数只允许白名单字段（类型、金额、币种、账本、账户、分类、标签、商户、备注、日期等），解析后生成待确认草稿，默认不能直接入账。

截图识别、文本识别、语音识别、快捷指令和 URL Scheme 均进入同一确认页；自动入账只在用户显式开启且满足高置信度、账户/分类唯一匹配和金额关系校验时允许。任何不确定结果都必须人工确认。

### 3.6 资产、预算、统计和存钱

- 资产页同时展示总资产、总负债、净资产、缺失汇率和本月与上月末的变化解释。
- 账户支持编辑名称、类型、排序、备注、隐藏/归档；有流水的账户只能归档。钱包支持停用/恢复，不能直接删除有余额或流水的钱包。
- 资产对账显示交易后的账户余额与当前钱包余额，并提供差异检查入口。
- 统计支持按日历、周、月、年、一级/二级分类、标签、账户、账本和现金流类型查看趋势与构成。
- 预算支持周/月/年总预算及分类预算；未来月份只展示设置，不伪造已用数据；历史月份保留最终状态。
- 存钱目标支持创建、编辑、暂停、完成、归档、增加/减少分配和完整历史；目标建议投入只作提示，不自动创建交易。

### 3.7 导入、恢复、同步和安全

- 导入先预览和映射，提供 iCost、支付宝、微信、云闪付等常用预设，并提供通用 CSV/XLSX 列映射以覆盖其他平台。
- 每批导入有指纹去重、错误行报告、可撤销批次和账本/币种确认。
- JSON 备份包含账本、账户、钱包、交易、分类、标签、预算、目标、关系和附件索引；恢复前创建当前快照。
- iCloud 默认关闭，开启后使用独立同步协调层处理 CloudKit 私有数据库、删除标记和冲突副本；余额始终由流水重算。
- 密码使用 Keychain，生物识别使用 LocalAuthentication；后台遮挡账务内容，不能在 URL Scheme 或日志中记录凭证。
- 秒开模式只负责启动后进入记账入口，不绕过锁屏或入账确认。

## 4. 分阶段交付

### 阶段 1：核心记账闭环

完成现有未提交的账本范围修复，统一交易草稿/提交服务，完整编辑、复制、搜索筛选、排序、商户和最近选择；补齐余额回滚、月份隔离和组合查询测试。

### 阶段 2：丰富交易属性

加入二级分类、标签、图片附件、模板、退款、报销、组合付款和批量操作；迁移录入、编辑和详情入口到统一服务。

### 阶段 3：自动化与 URL Scheme

加入周期账单、消费/账单分期、独立 URL Scheme，并把截图、文本、语音和快捷指令统一到确认入口。

### 阶段 4：资产、统计、预算与存钱

完成资产负债解释、对账、日历和多维统计，周/月/年总预算与分类预算，以及独立存钱目标闭环。

### 阶段 5：数据迁移与平台能力

扩充 50+ 常用币种、导入/恢复、iCloud 同步、密码与生物识别、后台遮挡、秒开模式和外观设置。小组件和位置附件仍不在本轮。

## 5. 错误处理与兼容性

- 金额、手续费、日期范围、币种、钱包、同钱包转账、换汇币种、退款上限、报销关联、分期参数和 URL Scheme 参数在保存前给出中文可操作错误。
- 归档账户、停用钱包、删除分类或失效模板不得静默替换；必须提示用户选择合法候选。
- 旧交易商户、标签、附件和关系字段为空时视为合法。
- 所有新模型加入版本化迁移；迁移前自动生成快照，迁移失败保留原库并给出恢复入口。

## 6. 测试与验收

纯逻辑测试至少覆盖：

- 各交易类型及手续费的 `WalletDelta`。
- 组合付款总额守恒、退款累计上限、报销个人承担额。
- 编辑/删除/批量失败回滚和历史交易迁移。
- 周期/分期唯一生成键和重复运行幂等。
- URL Scheme 白名单、非法参数和确认状态。
- 查询组合、账本/月份/币种隔离、统计预算和存钱分配独立性。
- 导入映射、指纹去重、批次撤销、JSON 恢复和同步冲突策略。

阶段验收标准：

1. 既有账本和历史交易可用，切换账本或月份不跨范围泄漏。
2. 任意新增、编辑、删除、退款、报销、分期和批量操作后，钱包、资产、预算和统计一致。
3. 除小组件和位置附件外，目标功能均有可用入口，不保留仅提示未完成的页面。
4. 不因日常小改动启动 Simulator；只在阶段性 UI/系统集成和最终回归时做必要运行。
