# 记账上下文标签“神奇效果”浮窗设计

日期：2026-07-30  
状态：待书面审阅  
范围：记账页“银行卡、AA、组合支付、优惠”四个上下文标签的浮窗、转场、键盘路由与取消/提交语义  
最低系统：iOS 26

## 1. 背景

记账页当前通过 `EntryContextControls` 展示“银行卡、AA、组合支付、优惠”等上下文标签。点击标签后，`TransactionFormSections` 直接显示 `EntryContextOverlay`，转场仅为轻微缩放叠加淡入，无法表达标签与浮窗之间的空间连续性。

本设计要求把被点击的标签本身作为浮窗的视觉来源：完整浮窗沿类似 macOS 窗口最小化“神奇效果”的非线性漏斗形路径展开；关闭时沿原路径反向收回同一标签。最终浮窗不按整屏居中，而是在标签和底部记账键盘上方的可用区域中居中。

## 2. 目标

- 四个标签分别从自身的实际屏幕位置展开浮窗，并准确反向归位。
- 完整浮窗内容参与非线性形变，包括文字、按钮、列表和输入内容。
- 浮窗最终位于标签行上方可用区域的中心。
- 页面底部只保留现有记账键盘；浮窗不得再嵌入第二套键盘。
- 浮窗打开时，键盘保持原位、清晰且可操作，并根据浮窗类型切换输入目标。
- 键盘上方的原页面内容使用中等模糊和暗色遮罩，形成明确层级。
- 明确区分“完成/选择”提交与“关闭/点击背景”取消。
- 遵守“减少动态效果”“降低透明度”、动态字体和 VoiceOver。
- 转场结束后不保留持续着色器或离屏渲染成本。

## 3. 非目标

- 不修改交易账务计算、SwiftData 模型、Schema 或迁移逻辑。
- 不重设计银行卡、AA、组合支付和优惠浮窗内部的信息架构。
- 不把本转场自动扩展到报销、不计收支、手续费、信用卡外币等其他标签。
- 不复刻或使用 macOS 私有实现；只复现已确认的视觉语义和运动特征。
- 不允许浮窗开合推动分类、金额、标签或键盘重新布局。

## 4. 已选方案

采用“转场专用网格形变层 + 动画结束后切换真实 SwiftUI 浮窗”。

### 4.1 方案说明

打开时，系统先测量来源标签和目标浮窗矩形。完整浮窗内容进入转场渲染层，通过自定义非线性网格形变，从标签大小和位置逐步展开至目标矩形。动画结束后，同位置、同尺寸的真实 SwiftUI 浮窗接管显示和交互。

关闭时，系统冻结浮窗当前画面，由转场渲染层接管，再沿相同路径反向收束回来源标签。转场完成后才提交待提交草稿并重新显示标签。

### 4.2 未选方案

1. 仅使用 `matchedGeometryEffect`、缩放、位移和裁剪：性能较轻，但只能形成矩形缩放，不能让完整内容呈现漏斗形扭曲。
2. 将浮窗拆成多条横向切片分别缩放和位移：能近似弯曲，但快速运动时可能暴露切片边缘，维护成本也高。

## 5. 布局与视觉层级

### 5.1 浮窗可用区

浮窗使用独立的目标区域，不以整个屏幕为居中基准：

- 上边界：记账页顶部安全区域或导航栏下方。
- 下边界：标签行顶部。
- 水平范围：记账页内容宽度，保留现有安全边距。
- 浮窗在该区域内水平和垂直居中。

四个浮窗使用统一宽度。目标宽度不超过现有 `480pt` 上限，并保留至少 `18pt` 水平边距。高度根据内容自适应；若内容高度超过可用区，则限制浮窗最大高度并让内部内容滚动。

### 5.2 页面分层

浮窗打开后，页面从低到高分为：

1. 原记账内容层：顶部至标签行底部应用中等模糊和暗色遮罩，全部禁止交互。
2. 清晰键盘层：现有 `EntryGlassKeypad` 保持原位置、原亮度和可操作状态。
3. 浮窗层：位于浮窗可用区中心，是除键盘外唯一可交互内容。
4. 转场层：仅在约 0.45 秒开合期间存在，覆盖来源标签与目标浮窗的联合范围。

背景模糊以约 `8pt` 为初始视觉标定值，允许在真机校准时于 `6–10pt` 范围微调；暗色遮罩目标不透明度为 `18%`。不得模糊或压暗底部键盘。

### 5.3 标签占位

点击后记录来源标签的实际屏幕矩形，并在原位置保留不可见占位，避免标签行重新排版。来源标签在浮窗存在期间隐藏，因为其视觉身份已转移到浮窗；其他标签保留模糊后的轮廓但不可操作。

关闭动画始终收回打开时记录的标签矩形。动画完成后才应用待提交数据并显示更新后的标签文字，避免账户名或金额变化引起收回路径跳动。

## 6. 动画设计

### 6.1 打开

默认总时长约 `0.45s`，使用快速起步、柔和减速、无回弹的曲线。

1. 标签立即显示轻微按压反馈。
2. 记录来源标签矩形、浮窗可用区和目标浮窗矩形。
3. 锁定页面、浮窗和键盘输入，隐藏来源标签。
4. 完整浮窗内容以压缩、扭曲状态出现在来源标签位置。
5. 浮窗沿弯曲路径向目标中心展开：靠近标签的一端短暂保持收束，远端先展开，形成连续漏斗形拖尾。
6. 文字、按钮、列表和数值与容器使用同一网格形变，不单独淡入。
7. 背景模糊与暗色遮罩同步渐入；键盘不移动、不缩放、不变暗。
8. 到达目标矩形后，无缝切换为同位置的真实浮窗并恢复浮窗与键盘输入。

### 6.2 关闭

点“完成”、选择银行卡、点关闭按钮或点击模糊背景都会触发关闭动画。

1. 锁定输入并冻结浮窗当前画面。
2. 隐藏真实浮窗，由转场层接管当前视觉。
3. 沿打开路径反向收束至来源标签矩形。
4. 背景模糊和暗色遮罩同步渐出。
5. 根据关闭原因提交或丢弃草稿。
6. 重新显示标签并恢复主金额键盘路由。

打开和关闭必须使用同一几何映射，保证方向可逆。动画中间不得出现矩形交叉淡化、内容提前消失或来源标签重复显示。

### 6.3 减少动态效果

系统开启“减少动态效果”时：

- 不执行网格扭曲。
- 使用约 `0.18s` 的短淡入淡出。
- 保持相同的目标位置、背景层级、提交/取消语义和键盘路由。

## 7. 展示状态与数据流

### 7.1 `EntryContextPresentationState`

新增单一展示状态，至少表达：

- 当前浮窗类型。
- 来源标签矩形。
- 目标浮窗矩形。
- 展示阶段：关闭、打开中、已展开、关闭中。
- 关闭意图：提交或取消。
- 当前键盘输入目标。
- 是否允许新的标签、浮窗或键盘交互。

页面同一时间只能存在一个上下文浮窗。打开或关闭动画期间忽略重复点击，避免重入和多层浮窗。

### 7.2 `EntryContextDraft`

浮窗打开时从 `TransactionFormState` 复制当前功能所需的最小字段：

- 银行卡：待选钱包/账户 ID。
- AA：总人数和基于主金额计算的 AA 结果。
- 组合支付：是否启用、付款项、付款账户、金额和当前高亮项。
- 优惠：优惠金额文本。

浮窗内的编辑先写入草稿，不直接修改正式表单。

### 7.3 提交与取消

提交路径：

- AA、组合支付、优惠点击“完成”或键盘的完成动作。
- 银行卡选择某个账户或“暂时不记”。

提交路径先标记待提交草稿，播放关闭动画，动画结束后一次性写回 `TransactionFormState`。

取消路径：

- 点击关闭按钮。
- 点击模糊背景。

取消路径播放相同的关闭动画，但动画结束后丢弃草稿并恢复打开前的上下文字段。

银行卡或 AA 浮窗打开期间，键盘仍可修改交易主金额。主金额属于记账主表单，不属于上下文草稿，因此取消浮窗时不回退主金额；AA 草稿中的应还金额随主金额实时重算。

## 8. 键盘路由

页面只保留现有的一套 `EntryGlassKeypad`，移除 `EntryContextOverlay` 内部嵌套的键盘。键盘 Binding 按展示状态切换：

| 浮窗状态 | 键盘输入目标 |
|---|---|
| 无浮窗 | 当前主金额目标 |
| 银行卡 | 交易主金额 |
| AA | 交易主金额；AA 结果实时重算 |
| 组合支付 | 草稿中当前高亮的付款项金额 |
| 优惠 | 草稿优惠金额 |

打开或关闭的 `0.45s` 转场期间暂时锁定键盘，进入“已展开”阶段后立即恢复。关闭完成后恢复原主金额目标，并刷新键盘重置标识，避免输入缓存串到错误字段。

## 9. 组件边界

现有 `EntryContextControls.swift` 已同时承载标签、形状、浮窗内容和业务辅助逻辑。本功能应做范围内拆分：

- `EntryContextControls`：只负责标签显示、点击和来源锚点上报。
- `EntryContextPresentationState`：展示阶段、关闭意图、输入路由和草稿生命周期。
- `EntryContextOverlay`：四种浮窗的真实可交互内容。
- `EntryContextOverlayHost`：可用区测量、背景模糊、层级和真实浮窗切换。
- `EntryGenieTransitionLayer`：转场进度、联合渲染区域和非线性网格形变。
- 形变着色器资源：只负责坐标映射，不读取或修改业务状态。
- `EntryComposerView`：持有单一展示状态与单一键盘，并提供正式表单 Binding。

拆分必须保持局部，不顺带重构其他记账页面或账务服务。

## 10. 形变渲染约束

- 形变作用于完整浮窗渲染结果，而不是只作用于外壳。
- 转场渲染范围必须包含来源标签与目标浮窗的联合矩形及采样余量，避免边缘裁切。
- 网格映射根据来源标签中心和目标浮窗边缘动态计算，不能假设标签固定在屏幕中央。
- 标签横向滚动后必须使用最新实际坐标。
- 真实浮窗与转场层在切换帧使用完全一致的目标矩形。
- 转场结束后销毁临时渲染层，不允许着色器持续参与普通输入、滚动或键盘渲染。
- 若形变层无法正常生成，降级为同路径缩放叠加淡入淡出；功能、提交和取消不能失效。

## 11. 无障碍与系统设置

- VoiceOver：浮窗完成展开后将焦点移至浮窗标题；关闭后返回来源标签。
- 动态字体：统一宽度不变，允许高度增长；超过可用区时内部滚动，不能裁掉操作按钮。
- 降低透明度：使用更实的半透明背景替代重度模糊，信息层级保持不变。
- 减少动态效果：按第 6.3 节降级。
- 转场期间向辅助技术表达稳定的展示状态，不暴露同时存在的来源标签、转场副本和真实浮窗。

## 12. 边界与恢复

- 页面尺寸、安全区域或动态字体变化时重新计算目标区域。
- 若几何变化发生在转场中，安全结束到确定状态，不保留半展开画面。
- 应用进入后台时结束中间帧；恢复后只能处于“已关闭”或“已展开”之一。
- 来源标签锚点临时不可用时，不启动网格转场，使用降级转场。
- 浮窗内容超高时只滚动浮窗内部，不遮挡标签行或侵入键盘。
- 动画期间不接受新的标签选择、浮窗关闭或键盘输入。

## 13. 验收与测试

### 13.1 状态测试

- 四种浮窗的草稿初始化值正确。
- “完成/选择”在关闭动画结束后提交。
- “关闭/点击背景”丢弃上下文草稿。
- 银行卡和 AA 浮窗取消时，期间修改的交易主金额仍保留。
- 组合支付和优惠取消时，键盘输入不会写入正式表单。
- 每种浮窗打开、关闭后键盘 Binding 路由正确。
- 快速重复点击不会创建第二个浮窗或打断状态机。

### 13.2 UI 与视觉测试

- 四个标签均从各自实际位置展开并返回同一位置。
- 标签横向滚动后，起点和终点仍准确。
- 浮窗最终在标签行上方可用区居中。
- 四种浮窗宽度一致，高度自适应，超高内容内部滚动。
- 背景模糊和暗色遮罩覆盖键盘上方区域；键盘亮度、尺寸和位置不变。
- 动画进度 `0% / 25% / 50% / 75% / 100%` 下检查漏斗轮廓、文字同步形变、边缘裁切和切层闪烁。
- 提交造成标签文字或宽度改变时，关闭路径不跳动。
- 浅色、深色、超大字体、VoiceOver、减少动态效果和降低透明度均通过回归。

### 13.3 性能测试

- 在真机连续开合四种浮窗，无明显掉帧、触控阻塞或残留图层。
- 转场以稳定 `60fps` 为最低验收目标；支持高刷新率的设备应尽量跟随系统刷新率。
- 动画结束后，普通键盘输入、标签横向滚动和分类交互不产生额外持续 GPU 成本。
- 使用性能工具确认转场临时纹理和渲染层在关闭后释放。

## 14. 完成定义

以下条件全部满足才视为实现完成：

1. 四个指定标签具有真实来源感、完整内容形变和可逆收回效果。
2. 浮窗在标签和键盘上方区域居中，页面及键盘无布局位移。
3. 页面只存在一套键盘，输入路由与提交/取消语义完全符合本规格。
4. 背景中等模糊并压暗，键盘保持清晰可操作。
5. 无障碍、系统动态设置、异常恢复和降级路径可用。
6. 真机性能与视觉分帧检查通过。
