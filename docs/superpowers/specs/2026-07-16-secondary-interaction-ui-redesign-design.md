# 高频二级交互与记账 UI 重设计

日期：2026-07-16  
状态：待用户复核  
范围：记一笔、交易详情、资产详情、预算、存钱目标，以及标签功能移除

## 1. 背景与目标

当前首页、资产页和存钱页已建立冷灰背景、透明玻璃表面、圆润卡片和轻量按压反馈，但“记一笔”、交易详情、预算管理及部分编辑页仍主要使用系统 `Form`、`List`、`Picker`。点击首页主要入口后，视觉语言和操作密度会明显断层。

本轮以本机 iCost 4.6.2 的实际交互和中国区 App Store 4.6.3 的公开说明作为层级参考，只借鉴“高频操作留在第一层、简单选择进入轻量弹层、复杂内容使用完整页面”的产品逻辑。不得复制 iCost 的颜色、页面布局、图标组合、数字键盘样式或具体视觉资产。

本轮首要成功标准是缩短日常记账路径。用户打开“记一笔”后应能立即选择分类、输入金额并保存，不需要滚动，也不需要先点金额输入框。

## 2. 已确认的产品决策

1. 采用“主操作面板 + 轻量选择层”的混合导航。
2. 记账金额使用页面内固定数字键盘。
3. 主按钮“完成”保存并关闭；次按钮“下一笔”保存并继续。
4. 换汇功能保留，既有业务规则不修改，只统一视觉和交互反馈。
5. 标签及其相关功能完整删除，已有标签数据永久丢弃，不写入备注或其他字段。
6. 大分类和子分类均使用独立透明玻璃卡片。
7. 点击大分类后，子分类从主分类下方展开为尺寸更小的玻璃卡片。
8. 展开过程中不绘制连接线、引导线或装饰轨迹。
9. 交易详情、资产详情、预算和存钱目标纳入同一轮二级页面重设计。

## 3. 设计原则

### 3.1 快速路径优先

默认路径只包含交易类型、分类、金额、账户、日期和保存操作。商户、备注、图片、组合付款、报销、优惠、手续费等按交易类型进入“更多信息”或独立轻量弹层。

### 3.2 层级与任务复杂度匹配

- 单一选择使用半屏弹层。
- 简短金额操作使用半屏任务弹层。
- 需要阅读上下文的详情使用导航推入。
- 新建账户、管理分类等管理任务使用完整页面。

### 3.3 原创视觉语言

沿用本项目已有的冷灰背景、系统蓝交互色、SF Symbols、透明玻璃和圆润几何。分类卡片是本轮的主要视觉特征，不复刻 iCost 的白色录入面板、分类排列和按钮配色。

### 3.4 数据安全优先

UI 改版不改变交易对钱包余额、预算、退款、报销、存钱目标和统计的既有账务语义。标签删除必须通过版本化迁移完成，迁移前保留可恢复快照。

## 4. 页面层级

```text
底部导航
├─ 记一笔：任务型大弹层
│  ├─ 账户选择：半屏弹层
│  ├─ 日期时间：紧凑弹层
│  ├─ 组合付款 / 手续费：半屏弹层
│  ├─ 更多信息：半屏弹层，可按内容扩展到大尺寸
│  └─ 新建账户、管理分类：完整管理页
├─ 交易详情：导航推入
│  ├─ 编辑交易：复用记账任务页
│  └─ 退款 / 报销：半屏金额弹层
├─ 资产详情：导航推入
│  └─ 账户交易详情：继续导航推入
├─ 预算概览：导航推入
│  ├─ 分类预算交易：继续导航推入
│  └─ 编辑预算：半屏金额弹层
└─ 存钱目标详情：导航推入
   ├─ 存入 / 取出：半屏金额弹层
   └─ 编辑目标：任务弹层
```

简单选择完成后立即回填并返回，不增加额外的“下一步”。取消二级页不得修改原值。录入页有未保存内容时下滑关闭，需要确认“放弃本次记录”；空表单可以直接关闭。

iPhone 使用底部弹层。iPad 和 Mac 使用尺寸受控的居中浮层，但字段顺序、按钮语义和数据流保持一致。

## 5. 记一笔主页面

### 5.1 页面结构

从上到下依次为：

1. 关闭、标题和当前账本入口。
2. 支出、收入、转账、换汇类型切换，以及承载“余额调整”的更多入口。
3. 主分类玻璃卡片横向区域。
4. 当前主分类的子分类玻璃卡片区域。
5. 分类路径、币种和大字号金额。
6. 账户、日期和更多信息上下文栏。
7. 固定数字键盘。
8. “下一笔”和“完成”。

页面打开后金额立即处于输入状态。用户不需要点击金额，也不依赖系统键盘弹出。

### 5.2 交易类型

- 支出和收入显示分类区域。
- 转账将分类区域替换为转出账户、转入账户和方向交换。
- 换汇保留换出金额、换入金额、账户、币种、汇率和手续费的现有业务规则。
- 余额调整放入更多入口，进入后显示增加或减少、目标账户和调整原因。

类型切换应保留仍然合法的账户选择，清理与新类型不兼容的分类、目标账户、手续费或换入金额。

### 5.3 主分类玻璃卡片

- 每个主分类是一张独立卡片，包含 SF Symbol 和分类名称。
- 卡片使用透明材质、细描边、顶部内高光和极轻背景阴影。
- 主分类横向滚动，不通过缩小字体强行容纳所有分类。
- 最近使用的合法分类优先，但仍尊重用户设置的分类顺序。
- 选中卡片轻微上浮并增加蓝色内描边，不使用实心蓝色填充。
- 主分类允许直接作为最终分类保存。

### 5.4 子分类展开

- 点击存在子分类的主分类后，子分类从该主分类的位置向下、向两侧展开。
- 动画只使用 `transform` 和 `opacity`。不绘制任何连接线或装饰轨迹。
- 子分类落位后排列在主分类下方，使用尺寸更小、层级更轻的独立透明玻璃卡片。
- 子分类最多占两行；数量较多时横向滚动，不压缩文字，不推挤数字键盘。
- 点击另一主分类时，旧子分类先收回原主分类位置，新子分类再展开。
- 点击当前主分类可保持主分类选中并收起子分类。
- 没有子分类的主分类直接选中，不播放空展开动画。
- 选择子分类后，金额区域上方显示“主分类 / 子分类”。
- 开启“减弱动态效果”时取消位移和缩放，只做短淡入。

### 5.5 金额与数字键盘

金额是页面唯一的大字号数字，使用等宽数字并根据币种显示正确精度。数字键盘支持：

- 0 至 9；
- 小数点；
- 删除；
- 加法与减法；
- 清空当前表达式；
- 对不完整表达式、连续运算符等非法状态给出字段内提示。

键盘按压只使用轻微缩放、透明度和触觉反馈。不得复制 iCost 的按键形状、排列比例或颜色。

### 5.6 上下文栏与更多信息

上下文栏只保留账户、日期和“更多”。标签入口不存在。

“更多信息”按交易类型展示商户或交易对方、备注、图片、组合付款、报销、优惠、手续费等已有合法字段。默认收起，已填写时在上下文栏显示摘要和已填写数量。

### 5.7 完成与下一笔

- “完成”校验并保存，成功后关闭录入页。
- “下一笔”校验并保存，成功后清空金额、商户、备注、图片和类型专属临时值。
- “下一笔”保留当前账本、交易类型、合法账户和分类。
- 保存失败、负余额待确认或数据库写入失败时，两种按钮都不得清空页面。
- 连续记账的次操作文案固定为“下一笔”，不得出现“保存再记”。

## 6. 轻量选择页

### 6.1 账户选择

账户选择使用半屏弹层，顶部为标题、搜索和新建账户入口。账户行展示名称、类型、币种和当前余额。信用账户可以显示可用额度。选择后立即回填并关闭。

转账和换汇根据交易规则过滤目标账户。没有合法目标时说明原因，不展示不可点击的长列表。

### 6.2 日期时间

日期时间使用紧凑弹层，提供日期、小时、分钟和“回到现在”。完成后一次性回填。取消不修改原日期。

### 6.3 组合付款和手续费

组合付款使用半屏弹层，逐行展示账户和金额，底部持续显示合计与交易金额差额。只有币种一致且合计等于交易金额时才能完成。

手续费弹层展示手续费金额和扣款账户。换汇和转账的手续费继续使用现有账务规则。

## 7. 交易详情

- 顶部为大玻璃摘要卡，展示分类图标、金额、交易类型、日期和账户关系。
- 分类使用“主分类 / 子分类”路径。标签区域不存在。
- 普通字段按交易信息、金额构成和备注分组，但不使用系统 `Form` 外观。
- 备注保持独立内容块，只在用户填写后出现。
- 图片使用横向缩略图区域，点击进入大图查看。
- 退款和报销显示为时间线，并展示原金额、已处理金额和剩余可处理金额。
- 底部悬浮玻璃操作栏以“编辑”为主操作。
- 复制、模板、退款、报销和删除进入更多菜单。
- 删除需要二次确认，明确说明会回滚账户余额。

编辑交易复用记账任务页和同一校验逻辑。编辑已有换汇时继续展示完整换汇字段。

## 8. 资产详情

- 保留当前银行卡式主视觉，不恢复快捷操作和卡片管理区域。
- 卡片内只展示账户名称、当前账户总金额和掩码卡号。
- 下方直接展示“这张卡的交易”，包含所有相关收入、支出、转账和换汇。
- 交易使用一张连续玻璃表面，内部以间距和单条分隔线区分。
- 点击交易进入统一交易详情。
- 空账户只显示简洁空状态，不添加“记一笔”“添加币种”等快捷按钮。

## 9. 预算

- 点击首页预算仪表盘进入预算概览，不直接弹出金额输入框。
- 顶部大玻璃卡展示总预算、已使用、剩余金额和当前周期。
- 分类预算使用独立透明玻璃卡片，展示分类、已用、剩余和进度。
- 点击分类预算进入该分类在当前预算周期内的交易列表。
- 卡片编辑入口打开半屏预算编辑器。
- 编辑器突出预算金额，并复用记账页数字键盘。
- 复制上期预算、周期切换和删除进入页面顶部或更多菜单，不挤占卡片正文。

## 10. 存钱目标

- 顶部大玻璃卡展示目标名称、已存、目标金额、剩余金额和预计完成时间。
- 主卡下方提供“存入”和“取出”两个独立操作。
- 存入或取出打开半屏弹层，包含金额、关联账户、日期和备注。
- 金额输入复用数字键盘，但不显示分类。
- 分配历史按时间排列，删除需要确认。
- 编辑、暂停、完成和归档进入右上角更多菜单。
- 页面必须明确说明存钱分配只用于目标规划，不会自动改变钱包余额。

## 11. 视觉系统

### 11.1 色彩

- 冷灰作为页面背景家族。
- 系统蓝或现有 `HomePalette.accent` 是唯一主交互色。
- 金额使用自适应主文本色，不因收入或支出直接变红或变绿。
- 分类颜色仅用于图标识别和极轻卡片染色。
- 错误、警告和破坏性操作使用系统语义色。

### 11.2 形状

- 页面主摘要卡使用大圆角。
- 主分类卡使用中等圆角。
- 子分类卡尺寸更小、圆角更紧凑。
- 按钮允许胶囊或圆形，但同一功能层级必须保持一致。

### 11.3 材质与无障碍

- 默认使用 `ultraThinMaterial` 或与现有玻璃组件一致的透明材质。
- 卡片包含内高光和细描边，不依赖大面积外发光。
- 分类卡片外不再套白色或玻璃大容器。
- 开启“降低透明度”时改用 `secondarySystemBackground` 等自适应实体表面。
- 所有文本与按钮满足系统动态字体、VoiceOver、对比度和至少 44 点触控区域要求。

## 12. 状态与错误处理

- 没有可用账户时，页面说明“请先创建账户”，并禁用“完成”和“下一笔”。
- 被归档或删除的默认分类回退到第一个合法主分类，不猜测子分类。
- 二级页取消、下滑或场景中断不丢失当前草稿。
- 金额、组合付款差额和必选账户错误显示在对应区域附近。
- 数据库或账务服务错误保留全部输入，并提供可重试提示。
- 负余额确认结束前不得关闭或重置表单。
- 空、加载和错误状态使用与最终布局相同的空间，避免页面跳动。

## 13. 标签功能删除

### 13.1 产品范围

以下内容全部删除：

- `TransactionTag` 的运行时业务模型和服务；
- 记账、编辑和详情中的标签字段；
- 搜索、筛选、批量编辑和统计中的标签维度；
- 标签管理设置页；
- 模板、周期任务、自动记账、智能草稿和 URL 草稿中的标签解析；
- 新备份、导出和云端同步中的标签记录与关联 ID。

备注保持原样。标签名称不得追加到备注、商户、分类或其他字段。

### 13.2 数据迁移

1. 为移除标签后的存储结构增加新的版本化 schema。
2. 在打开新 schema 前创建 `pre-migration` 数据库快照，并更新快照版本标记。
3. 迁移阶段解除所有交易与标签关系，清空模板及自动化快照中的标签 ID，并删除全部标签记录。
4. 新运行时 schema 不包含标签实体、交易标签关系或模板标签字段。
5. 旧 schema 定义作为冻结的迁移兼容声明保留，用于识别旧数据库，不进入新版本业务查询和界面。
6. 迁移失败时不得继续以部分迁移状态运行，用户可通过现有迁移恢复页恢复快照。

### 13.3 兼容策略

- 新备份不包含标签。
- 旧备份仍可解码标签和标签 ID，但恢复时直接丢弃它们，其余交易内容正常恢复。
- 旧周期任务、模板和自动化快照中的额外标签字段在解码时被忽略并在下次保存时移除。
- URL 白名单移除 `tags`。包含该参数的旧链接返回“当前版本不再支持标签”，不得静默创建缺少用户预期属性的交易。
- 云端旧文档中的标签集合和交易标签 ID 在导入时丢弃，不重新创建本地标签。

## 14. 组件与数据边界

- `EntryComposerView` 组织录入页面，不直接修改余额。
- `GlassCategoryCard` 统一主分类和子分类的材质、选中态与按压反馈。
- `ScatteredSubcategoryLayout` 只负责布局与动效，不负责业务选择。
- `EntryAmountPad` 只负责数字表达式和编辑操作。
- 账户、日期、组合付款等弹层通过绑定或明确的选择结果回填。
- `TransactionFormState` 表达当前输入状态。
- `TransactionDraft` 是新建、复制、编辑、模板和自动化的共同边界。
- `LedgerService` 与现有账务计算服务继续作为唯一写入入口。

## 15. 验证与验收

### 15.1 自动验证

- 数字键盘的数字、小数、删除、加减和非法表达式测试。
- 主分类直接保存、子分类保存、切换主分类和无子分类测试。
- “完成”和“下一笔”的保存与重置测试。
- 支出、收入、转账、换汇、余额调整和组合付款账务回归。
- 标签迁移测试：关系解除、标签数量归零、备注不变、交易数量和金额不变。
- 旧备份兼容测试：标签被丢弃，其余内容恢复成功。
- 旧 URL `tags` 参数返回明确错误。
- 模板、周期任务、自动化快照和云端文档不再产生标签数据。

### 15.2 UI 与视觉验证

- 记一笔打开后无需额外点击即可输入金额。
- 主分类和子分类均为独立玻璃卡片，外部没有统一白色容器。
- 子分类从主分类下方展开，页面上不存在连接线。
- 小尺寸 iPhone 上数字键盘、“下一笔”和“完成”始终可见。
- 浅色、深色、降低透明度和减弱动态效果均可正常使用。
- 账户、日期、组合付款、预算编辑和存钱操作弹层均能取消且不修改原值。
- 交易详情、资产详情、预算和存钱目标的导航返回位置稳定。

### 15.3 数据一致性验收

升级前后以下数据必须一致：

- 交易数量、金额、日期、备注、商户和分类；
- 账户、钱包和余额；
- 预算、退款、报销和统计结果；
- 存钱目标和分配记录；
- 模板和自动化中的非标签字段。

升级后标签数量必须为零，运行时不存在任何标签入口或标签查询。

## 16. 明确不在本轮范围

- 不改变换汇、转账、组合付款、退款或报销的账务语义。

- 不恢复资产详情中已删除的快捷操作或管理区。
- 不重新设计首页一级信息架构和底部导航。
- 不新增云端服务、位置附件或新的账户类型。
- 不复制 iCost 的视觉素材、页面比例、分类排列或键盘外观。
