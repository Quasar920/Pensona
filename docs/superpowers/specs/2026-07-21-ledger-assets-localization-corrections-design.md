# 流水页、资产页与全量本地化修正设计

日期：2026-07-21
状态：待书面审阅
范围：流水页月份导航与搜索收起、资产页四模块卡片、全应用简中/繁中/英语/日语本地化

## 1. 背景

本轮来自真机界面检查，已确认三个问题：

1. 流水页的月份与前后月按钮缺少清晰的三段式对齐，月份不在屏幕视觉中心。
2. 流水页退出搜索后，控件仍可能保持展开搜索框状态，没有稳定恢复为圆形放大镜按钮。
3. 资产页的 `AA / 报销 / 借入 / 借出` 四张模块卡片纵向过高；同时，当前本地化目录只覆盖少量界面文字，英语、日语和可能的繁体中文界面仍会回退到简体中文。

流水页和资产页已经通过预览图确认视觉方向。本规格将确认结果转化为明确的布局、状态和验收要求，并采用全应用本地化扫描方案补齐四种语言。

## 2. 已确认方案

### 2.1 流水页

- 月份导航保持单独一行。
- 上一个月按钮靠页面左侧，下一个月按钮靠页面右侧。
- 年月选择控件严格位于屏幕水平中心，不受左右按钮宽度影响。
- 左右按钮继续使用相同尺寸的圆形 Liquid Glass 控件。
- 点击搜索关闭按钮后，清空搜索词、结束输入焦点并收起键盘，搜索控件恢复为圆形放大镜按钮。

### 2.2 资产页

- `AA / 报销 / 借入 / 借出` 保持 2 × 2 排列。
- 两列继续占满页面现有可用宽度，保留当前页面左右边距和列间距，不额外增加两侧留白。
- 删除四张卡片中的 `0 项` 数量行。
- 每张卡片仅保留“图标与标题”和“金额”两行。
- 卡片只做纵向压扁，目标总高度约 88pt；四张卡片等高、等宽。
- 缩小内部纵向间距和上下内边距，但保持金额和标题可读，不缩小触控范围到 44pt 以下。

### 2.3 本地化

采用“全应用用户可见文案扫描并补齐”的方案：保留现有代码结构和以简体中文源文案为主的字符串目录，不在本轮大规模改造成语义化键；所有用户可见静态文案、动态提示、错误信息、无障碍标签和日期表达均覆盖简体中文、繁体中文、英语和日语。

未采用的方案：

- 只翻译当前两个页面：改动小，但无法解决其他页面和弹窗继续显示中文的问题。
- 全量改造为语义化字符串键：长期维护更统一，但会显著扩大本轮差异并增加与现有未提交改动冲突的风险。

## 3. 流水页详细设计

### 3.1 月份导航布局

月份行使用“边缘操作层 + 独立居中内容”的结构，而不是依靠普通 `HStack` 中三个控件自行分配空间：

- 底层横向容器放置左箭头、弹性空间和右箭头。
- 年月选择按钮作为居中层覆盖在容器中心。
- 年月继续带向下箭头，点击后打开现有年月选择器。
- 左右滑动切月手势保持不变。
- 左右按钮保留现有无障碍标识 `bill-month-previous` 和 `bill-month-next`。

该结构保证账本名称、顶部按钮数量或本地化文本长度变化时，年月仍以屏幕中心为基准。

### 3.2 搜索状态

搜索控件继续保留收起和展开两个明确状态：

- 收起：圆形放大镜按钮。
- 展开：放大镜、文本输入框和关闭按钮组成的胶囊搜索框。

关闭动作按固定顺序执行：

1. 将搜索焦点设为 `false`，让键盘立即退出。
2. 清空当前搜索词，使账单列表恢复完整月份结果。
3. 在现有响应式动效中将 `isSearchExpanded` 设为 `false`。

搜索输入框消失后不得因为残留焦点、视图重新出现或任务刷新而再次展开。重新点击圆形放大镜才允许进入展开状态。

### 3.3 边界行为

- 搜索为空时关闭仍必须收起。
- 搜索有内容时关闭必须同时清空结果过滤。
- 切换月份不应改变搜索控件的展开/收起状态；关闭后的状态不得因切月恢复。
- 动态字体下年月文字可缩放或适度压缩，但不得与左右圆形按钮重叠。
- VoiceOver 顺序为：上一个月、年月选择、下一个月。

## 4. 资产页详细设计

### 4.1 网格与尺寸

模块区域继续使用两个等宽弹性列：

- 页面水平内边距沿用 `LedgerLayout.pagePadding`。
- 列间距和行间距固定为 12pt。
- 不对网格添加额外 `maxWidth`、居中窄容器或额外水平内边距。
- 卡片目标总高度约 88pt，标准字体下四张卡片视觉一致。

### 4.2 卡片内容

内容从三行改为两行：

1. `Label`：模块图标与 `AA / 报销 / 借入 / 借出` 标题。
2. 金额：保留等宽数字和现有隐藏金额/缺失汇率逻辑。

删除数量文本，不用空白占位符保留原高度。内部使用 6pt 行间距、12pt 垂直内边距和 16pt 水平内边距；卡片设置 88pt 最小高度，动态字体需要更多空间时允许自然增高。

### 4.3 可访问性与动态字体

- 卡片视觉变矮后，整个卡片仍是可点击区域，触控高度不低于 44pt。
- 标准字体按约 88pt 高度呈现。
- 辅助功能大字号下允许卡片自然增高，避免标题或金额截断。
- 隐藏金额状态继续显示 `••••`；缺失汇率继续显示 `--`。
- 数量仍保留在数据模型和模块详情中，本轮只删除资产首页卡片上的数量展示，不删除统计逻辑。

## 5. 全应用本地化详细设计

### 5.1 覆盖范围

扫描 `MultiCurrencyLedger` 下全部 Swift 源文件和 `Localizable.xcstrings`，覆盖：

- 四个主页面、底部导航、设置和所有二级页面。
- Sheet、确认对话框、警告、空状态、加载状态、按钮和表单标签。
- 记账、编辑、导入、备份、同步、识别、预算、计划、AA、借贷和资产模块中的用户可见提示。
- 无障碍标签与提示。
- 用户可见的校验错误和业务错误。
- 带插值或格式参数的动态文案。
- 年月、日期和时间等随语言变化的格式。

不纳入本地化的内容：调试日志、预览环境变量、持久化枚举原始值、通知名称、测试标识、货币代码、用户输入、账本/账户/分类名称以及外部服务原始错误文本。

### 5.2 字符串接入规则

- `Text`、`Button`、`Label`、`Section`、`navigationTitle` 等支持 `LocalizedStringKey` 的静态文字继续直接使用本地化字符串。
- 需要先计算、拼接、存入模型或作为普通 `String` 传递的用户文案使用 `String(localized:)`，避免普通字符串插值绕过字符串目录。
- 包含变量的文案使用可校验的格式参数或本地化插值，四种语言的参数数量和类型必须一致。
- 不通过手工字符串拼接组织不同语序，例如数量、货币、账户名称和错误原因应由完整本地化句子承载。
- 业务枚举的用户可见标题在展示边界本地化；持久化 `rawValue` 保持不变。

### 5.3 日期与年月

移除仅适用于简体中文的 `chineseYearMonth` 用户界面格式，改为读取当前 SwiftUI `Locale` 的本地化年月格式：

- 简体中文示例：`2026年7月`
- 繁体中文示例：`2026年7月`
- 英语示例：`July 2026`
- 日语示例：`2026年7月`

格式由系统日期格式能力生成，不通过语言分支硬编码月份名称。年月选择器中的“年 / 月”等单位也必须进入字符串目录。

### 5.4 翻译质量规则

- 简体中文作为源文案，修正明显不一致的术语后再翻译。
- 繁体中文使用自然繁体词汇，不仅做机械字形转换；例如资产、设置、数据、账户等采用目标地区可理解且全应用一致的表达。
- 英语使用简洁的 iOS 界面语气，按钮优先使用动词，避免逐字直译导致过长。
- 日语使用自然、简洁的应用界面表达，统一敬体/非敬体风格，不混用简体中文汉字词。
- `AA`、货币代码和用户数据等确实应跨语言相同的内容进入明确允许列表，不把相同文本误判为翻译缺失。

### 5.5 运行时语言切换

继续由 `AppPreferences.language` 提供当前 `Locale`，并由根视图注入环境。切换语言后根内容重新建立，所有主页面、已存在的格式化日期和普通字符串计算结果均应使用新语言；不得要求用户重启应用。

## 6. 数据流与错误处理

本轮不改变账务数据模型或计算结果：

- 搜索关闭只影响 `BillPageState.searchText`、搜索焦点和 `isSearchExpanded`。
- 月份导航只改变布局，不改变现有 `selectedMonth` 与查询逻辑。
- 资产模块数量仍由快照计算并可供详情页使用，只是不再在首页卡片渲染。
- 本地化只改变用户可见字符串和格式，不改变持久化值、查询条件或导入导出协议。

如果业务错误来自应用自身，错误类型应返回可本地化文案；如果来自系统或外部服务，优先展示系统已经本地化的描述。不得为了翻译而丢弃底层错误信息，也不得将内部调试细节直接暴露给用户。

## 7. 测试与验证

### 7.1 自动化测试

扩展 `LocalizationCoverageTests`：

- 字符串目录中的所有用户可见条目都必须包含 `zh-Hans`、`zh-Hant`、`en` 和 `ja` 非空翻译。
- 四种语言的格式参数集合必须一致。
- 英语、日语和繁体中文不得无意回退为简体中文；跨语言允许相同的条目使用小型显式允许列表。
- 扫描常用 SwiftUI 用户文案入口，确保静态源字符串已经进入字符串目录。
- 验证四种语言的年月格式不会固定输出简体中文格式。

为搜索状态补充可测试的状态转换，至少覆盖：展开、输入、关闭、清空、失焦和再次展开。若焦点本身不适合单元测试，则通过 UI 测试验证键盘退出和圆形搜索按钮重新出现。

### 7.2 构建与界面验证

- 运行受影响的单元测试和项目构建。
- 分别以简体中文、繁体中文、英语和日语启动流水页、资产页、记账页、计划页、报表页和设置页。
- 检查弹窗、空状态、错误提示和二级页面，不只检查 Tab 标题。
- 流水页验证月份始终居中，左右按钮贴合现有页面边距，搜索关闭后恢复圆形按钮。
- 资产页验证两列宽度与原页面一致、没有新增侧边留白、`0 项` 完全消失、标准字体下卡片约 88pt 高。
- 使用大号动态字体验证月份不与按钮重叠、资产卡片可自然增高且金额不截断。

## 8. 验收标准

- 流水页年月在屏幕水平中心，左右切月按钮分别位于页面两侧。
- 关闭搜索后搜索词清空、键盘退出、控件恢复为圆形放大镜；刷新与切月不会让它自动重新展开。
- 资产页四模块保持满宽 2 × 2 网格，不增加左右留白。
- 四张模块卡片删除 `0 项`，只显示标题和金额，并明显比当前版本更扁。
- 简体中文、繁体中文、英语和日语下，所有用户可见应用自有文案均使用所选语言。
- 日期、年月、数量和动态句子符合目标语言语序与格式。
- 本地化覆盖测试、相关状态测试和项目构建通过。
- 不改变账务数据、资产汇总、搜索查询语义或持久化协议。
